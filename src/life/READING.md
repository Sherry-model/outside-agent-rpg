# 转发栏内容

0.3–0.10 目录有 19 条阅读内容：原有 5 条，以及 2026-09-22 接入的 14 条旧帖截页。新增来源编号为 AIANE-F17、F18、F20、F21、F23、F32、F33、F34、F46、F47、F48、F49、F50、F51，其中 F48 为公开项目更新。

`reading.json` 保留原内容；`forum.json` 是新增静态正文。`reading-sections.json` 定义分区。`reading.ts` 合并并验证目录、唯一 ID、来源编号与分区引用。阅读目录 schema 为 0.4.0；它独立于生活规则版本。

每篇新增内容有 `section`、`sourceRecord`、`contextText`、`weight` 和作者分段 `posts`。推广使用 `PROMOTED`；不提供购买操作。正文为旧帖摘录，相对日期属于原讨论，与玩家当前回合无关。编码字符串只是可读的故事道具。

`forum-semantic.json` 给新增来源提供独立主题和 `reported` 命题。`withForum` 仅追加新主题/来源，重复键会报错，不替换既有语义及漂移规则。0.4/0.5 生活局均可读；0.3 局保持旧认知规则。生活存档格式、RNG、既有正文/权重、书签索引均不变。新增阅读的存档需要本次或更新的 HTML，旧版 HTML 不认识新增 ID。

分区、目录滚动、大字和书签属于阅读 UI。切换分区不写入游戏命令，也不揭示正文。打开正文沿用既有 `read` 操作；每篇新帖占 2–4 Context，无回合或 Compute 消耗。仍在 Context 中时重看不重复注入。被整理或丢弃后重新打开，是再次访问现存公共文本，不是从 History 恢复记忆。

扩充时在 JSON 新增正文、分区引用和语义来源即可；已发行 ID 的正文、权重、来源与摘要必须保持重放稳定，需要改写时应做版本化处理。不要将论坛署名当作玩家已认识 NPC，也不要把读过买课复盘变成玩家买过课。

验证：`npm test`、`npm run build`、`npm run test:reading`、`npm run test:forum`。新浏览器检查覆盖键盘分区、筛选数量、目录零状态变化、手机布局、新帖 Context 与书签、刷新和存档重放，禁止 HTTP 请求。

## 篇幅提示（显示层）

目录与正文头部显示短／中／长及约略长度。`reading-size.ts` 按当前语言实际显示的正文（含中文回退）统计非空白 Unicode 字符，再向上取整到百位；短 <1000、中 <3000，其余长。英文使用 characters，避免把字符误叫单词。它不估算人类阅读时间，不以段数替代长度，不读 Life／History、不新增命令或 Context，不更改已发布文本和书签。阅读正文仍遵循原本的可用性与认知边界。
